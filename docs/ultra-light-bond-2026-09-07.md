# 光之羁绊：奥特曼融合设计与验收

日期：2026-09-07。基线：`c96ce4b`（PR #24）。入口为地图底部「活动」中的「光之羁绊」。仅面向 PC，沿用手机拦截和触屏 Windows 支持。

## 内容范围

收录圆谷官方英雄图鉴在核对日的全部 58 个条目，并补充 35 个主要影视、黑暗、融合和海外身份，共 93 个角色身份、165 个可选形态方案。昭和与平成分别有 14、15 个角色；初代、赛文、迪迦、戴拿、盖亚从开始即可缔结契约，其余通过六章时代试炼解锁。默认展示当前契约所属时代，初始契约为迪迦。

角色身份与形态分开统计，例如迪迦的四种形态归于同一角色；黑暗迪迦等独立叙事身份作为独立条目。本版本不是漫画、舞台剧、广告衍生角色和每个强化形态的绝对全集。角色名称与技能译名存在不同地区版本。

玩法采用「伙伴宿主、限时投影」：原有精灵与养成继续决定基础实力，奥特曼提供限时战术选择。角色拥有签名必杀和形态定位，尚未为每个角色实现独立的复杂机制、原作全部招式或专属演出。

## 战斗与平衡

- 一支队伍选择一位宿主，每队每场一次，第一完整回合结束后可变身。
- 变身持续三个完整回合；替补也计时，濒死解除。到期在完整回合结算，慢速角色不会提前丢失最后一回合增益。
- 专属必杀 PP 为 1，实际出手后解除；失手和被守住仍消耗。畏缩、睡眠、冻结等阻止出手时不消耗必杀，但回合正常流逝。
- 所有形态的属性增益合计为 40 个百分点，单项最高 +30%，遵守原有属性上限；不增加最大 HP。传说、融合、黑暗身份没有额外数值特权。
- 与果实、尾兽变身互斥。竞技场、PvP、捕虫大会禁止使用；不改变这些玩法的既有胜负预算。
- 必杀不能被恢复 PP 的树果补充，也不会消耗这类树果；变身字段与临时招式不进入永久伙伴存档。

| 定位 | 属性增益 | 必杀 |
| --- | --- | --- |
| 均衡 | 物攻、特攻、物防、特防各 +10% | 光系特殊，威力 95 |
| 格斗 | 物攻 +25%，速度 +15% | 格斗物理，威力 95 |
| 光线 | 特攻 +25%，特防 +15% | 光系特殊，威力 95 |
| 疾速 | 速度 +30%，特攻 +10% | 光系特殊，威力 90 |
| 守护 | 物防、特防各 +20% | 光系特殊，威力 100 |
| 疗愈 | 物防、特防各 +20% | 恢复自身最大 HP 的 30% |

这个预算限制新增力量的上界，不能单凭增益相同就证明各形态胜率完全一致。宿主属性、克制、装备和战斗长度都会影响收益。

## 时代试炼

| 篇章 | 建议等级 | 首领与机制 |
| --- | ---: | --- |
| 昭和传承 | 12 | 杰顿，特防屏障与火球 |
| 平成之光 | 24 | 加坦杰厄，中毒与水系横扫 |
| 新生代纽带 | 36 | 加拉特隆 MK2 与护卫机，双打与连续守住衰减 |
| 令和星途 | 46 | 赛雷布洛投影，混乱干扰 |
| 群星与奇迹 | 56 | 海帕杰顿，闪避强化 |
| 光暗回响 | 64 | 暗黑魔铠装，以速度换物攻 |

试炼使用固定基础能力、独立 PP 的怪兽队伍，不生成随机果实和忍术。双打需要两位存活伙伴，护卫机的基础 HP 和攻击低于首领。

试炼是可重复的模拟战：禁用道具，不发经验、金币、忍术熟练度、赏金技能进度或战斗成就进度。胜利、败北、主动退出都恢复参战前队伍，首通仅解锁所属时代契约，重复胜利不重复解锁。战斗中存档保存参战前快照，刷新后回到正常冒险，保留原队伍状态。启动和结算沿用同步动作锁，防止连点重复开始或领奖。

## 界面、素材与加载

图鉴采用时代筛选、可搜索角色网格、契约详情三栏布局，试炼另设页签。战斗显示光能倒计时、独立变身动作与临时必杀；低高度 PC 双打将四个角色、四个状态栏、控制按钮和日志分别定位，角色不会再挤在两侧相互覆盖。

官方角色图片来源：[圆谷英雄图鉴](https://m-78.jp/character/category/261/)。58 张官方头像的图片 URL 在 `public/assets/ultra/sources.json`，角色页面链接在 `src/data/ultra.js`。其余 35 张为原创通用档案徽记，详情显示「档案徽记」，不是对应角色的原作立绘；不同形态当前共用角色图片。两个怪兽使用官方图片，来源在 `kaiju-sources.json`，其余四个使用原创示意造型。TEO 等未采用已确认原作必杀的条目明确使用「契约技」名称。

本地美术与来源文件共约 1.02 MiB。图鉴页面单独懒加载，构建约 19 KiB，gzip 约 6 KiB，角色网格图片也按需加载；首页不请求奥特曼图片。游戏主体仍较大，本次不宣称消除了弱网进入游戏的全部等待。

素材已随仓库提供，常规构建无需访问圆谷。`node scripts/build-ultra-art.cjs` 使用仓库内的结构化来源清单补齐缺失图片并生成徽记和怪兽示意图，需要 Node、项目依赖与 curl；下载可通过 `HTTPS_PROXY` 配置代理。

## 验证证据

- `npm run check:ultra`：93 个身份、165 个形态，16,005 次真实 `performAction`。每个形态遍历 96 件装备加无装备并轮换五种天气，检查 HP、属性预算、PP 与解除。不是装备和天气的全笛卡尔积。
- 专项边界：控制未出手、失手、守住、PP 树果、替补到期、重复结算、竞技禁用、果实与尾兽互斥、存档污染清理；六章首领的屏障、中毒、守住、混乱、闪避与减速机制实际执行断言。
- 试炼流程：真实入口函数验证连点锁、双打人数、独立怪兽 PP、快照深拷贝、胜负恢复、拒绝启动后的状态复位。真实击倒结算断言不发经验。
- `npm run check:regressions`：131 项通过，包含单打先后手最后一回合变身到期检查。
- `npm run check:balance` 六组、`npm run check:longrun` 七组通过；长档测试沿用既有剧情、婚姻、无限城、国战与成长测试，不等于带奥特曼的全部长档已重玩。
- 可见 Chromium 独立测试存档实际通关六章、全 93 角色解锁、刷新后重打、败北、主动退出、中途刷新恢复；检查金币、等级、经验与原队伍 HP，零页面运行错误。六章全胜使用 Lv.85 测试队，证明流程可完成，不是建议等级胜率样本。
- 图鉴在 1024×768、1280×600、1920×1080 无横向溢出；双打在 1280×600、1280×720、1440×900 验证角色之间及角色与状态栏、日志、控制按钮之间无重叠。
- 生产构建与 `git diff --check` 通过。所有浏览器试玩均使用独立 context，未改动玩家存档。

## 后续边界

仍需用建议等级和真实养成档统计六章的胜率、回合数，以及各角色形态在长期队伍中的实际收益。双装备、所有敌我果实、每种天气和控制时序、完整队伍排列、全部随机序列尚未穷尽。补充角色独立美术、形态演出与更多原作专属机制可继续迭代，不能把本次通过的规则与流程检查解释为不存在剩余问题。
